# notification

## Purpose
Displays in-app notifications generated by backend events: friend requests/acceptances, post and comment likes, new comments/replies, chat messages, and admin announcements. `NotificationNotifier` fetches the list from Supabase, tracks unread count, and supports marking individual notifications or all notifications as read using optimistic updates (reverts on failure). The `AppNotification` entity carries contextual IDs (`postId`, `commentId`, `chatRoomId`) so the notification screen can deep-link to the relevant content. FCM push delivery is handled separately in `core/services/fcm_service.dart`; this feature only manages the in-app notification center.

## For AI Agents

### Working In This Directory
- The repository class `NotificationRepository` lives in `data/repository/`, not `domain/` — this is an architectural deviation from other features. Do not create a duplicate in `domain/`.
- `markAsRead` and `markAllAsRead` use optimistic updates: update local state immediately, call server, revert on failure.
- `addNotification(AppNotification)` is called by `FcmService` when a push arrives while the app is foregrounded — it prepends to the list.
- `unreadNotificationCountProvider` is used by the navigation bar badge; watch it for badge rendering, not the full `notificationProvider`.
- `NotificationType` values are uppercase JSON strings (`FRIEND_REQUEST`, `POST_LIKE`, etc.) — always use `@JsonValue` annotations when adding new types.
- Deep-link routing on notification tap uses `postId`, `commentId`, `chatRoomId` from the entity to navigate to the right screen.

### API Endpoints
Backed by Supabase (via `notification_api_impl.dart`):
- `GET /notifications` — fetch all notifications for current user
- `PUT /notifications/{id}/read` — mark single as read
- `PUT /notifications/read-all` — mark all as read
